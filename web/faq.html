Should I use Speed, Distance, or Hybrid mode?

应该选择速度、距离还是混合模式？

Use Speed mode if you want faster, more flexible scrolling after a short adjustment period. It estimates scroll speed from wheel event timing, so a quick flick can replace many small wheel steps. This is useful for long pages, code, and document lists.

如果你愿意适应一种更灵活、更省力的滚动方式，建议使用速度模式。它会根据滚轮事件的时间间隔估算速度，快速拨动滚轮时会明显加速，一次快速滚动可以替代过去很多次连续滚动。它适合长页面、代码和文档列表。

Some mice or receivers do not report wheel event timing very consistently. If Speed mode sometimes accelerates unexpectedly, Distance mode is usually the better choice.

部分鼠标或接收器的滚轮事件时间不够稳定，速度模式可能会误判为快速滚动，出现突然加速。如果遇到这种情况，通常更适合改用距离模式。

Use Distance mode if you want predictable scrolling closer to a traditional mouse wheel. Each wheel event contributes a fixed distance, and the smoother only changes how that distance is released over time.

如果你希望滚动距离稳定、可预测，更接近传统鼠标滚轮，建议使用距离模式。每次滚轮事件都会贡献固定距离，平滑器只改变这段距离释放出来的节奏。

Use Hybrid mode if you want Speed mode's acceleration without short scrolls falling below a predictable minimum. It follows the speed-based output and uses Wheel Tick Distance as the per-event distance floor.

如果你希望保留速度模式的加速效果，同时避免短滚动距离过小，建议使用混合模式。它跟随速度模式的输出，并以“单次滚轮距离”作为每次事件的距离下限。

Why is there a dead zone at the start of scrolling?

为什么开始滚动时有死区？

This is a known libinput issue: Disable hi-res wheel event initial accumulation for uinput (#1129). It has been fixed upstream, but the fix may not have reached your distribution yet.

这是 libinput 的一个已知问题：Disable hi-res wheel event initial accumulation for uinput (#1129)。上游已经修复，但你的发行版未必已经包含这个修复。

If your system still has this behavior, installing a newer libinput can help:

如果你的系统仍然有这个现象，可以尝试安装更新版本的 libinput：

sudo apt install meson ninja-build libmtdev-dev libevdev-dev libudev-dev libwacom-dev
git clone https://gitlab.freedesktop.org/libinput/libinput.git
cd libinput
meson setup builddir --prefix=/usr -Ddocumentation=false -Dtests=false -Ddebug-gui=false
ninja -C builddir
sudo ninja -C builddir install

Restart your desktop session after installation.

安装后请重启桌面会话。

If scrolling works in most applications and only one application has trouble, see the application compatibility steps below instead.

如果大多数应用都能正常滚动，只有某个应用出现问题，请改为参考下方的应用兼容性排查步骤。

Why does smooth scrolling or the first wheel step fail in some applications?

为什么某些应用滚动不顺畅，或第一次拨动滚轮没有反应？

Smooth Scroll's continuous motion requires applications to support high-resolution wheel input. If scrolling works in most applications but one application does not scroll, moves in jumps, or ignores the first wheel step, that application may be using an older whole-step input path.

Smooth Scroll 的平滑滚动需要应用支持高精度滚轮输入。如果大多数应用滚动正常，只有某个应用不响应、出现跳动，或忽略第一次滚轮操作，该应用可能正在使用只按整格滚动的旧式输入方式。

Use this troubleshooting order:

请按以下顺序排查：

  1. If you added GDK_CORE_DEVICE_EVENTS=1 to the application's launch command, shortcut, or environment settings, remove it, fully quit the application (including background processes), and reopen it. If you have not set this option, continue to the next step.
  2. If scrolling still does not work, enable Force Passthrough for this application to restore normal wheel scrolling. Smooth Scroll will no longer smooth scrolling in that application; other applications are unaffected. Follow the GNOME window rules or KDE Force-Passthrough rules guide for your desktop.
  1. 如果你曾在应用启动命令、快捷方式或环境设置中加入 GDK_CORE_DEVICE_EVENTS=1，请先移除它，完全退出应用（包括后台进程）后重新打开。如果没有设置过这一项，可以继续下一步。
  2. 如果仍然无法正常滚动，可以为该应用启用强制透传，恢复普通滚轮操作；该应用将不再使用 Smooth Scroll 的平滑滚动，其他应用不受影响。请按你的桌面环境查看 GNOME 窗口规则或 KDE 强制透传规则说明。

Smooth Scroll does not convert continuous motion into legacy whole-step events. That conversion can make a page look stationary while Smooth Scroll is still decelerating. For example, an opposite wheel step at that moment may only brake the hidden motion instead of scrolling immediately in the other direction. Free Spin, Drag View, and Auto Scroll also depend on whether scrolling is still active, so their response could become similarly unexpected. Force Passthrough avoids this mismatch by returning the application to its normal wheel behavior.

Smooth Scroll 不会把平滑滚动转换成一格一格的旧式事件。这种转换会让页面看起来已经停下，但 Smooth Scroll 实际上仍在减速。例如，此时反向拨动滚轮可能只会刹车，而不会立即向反方向滚动。Free Spin、Drag View 和 Auto Scroll 也依赖当前是否仍在滚动，因此同样可能出现不符合直觉的响应。强制透传通过让应用恢复普通滚轮操作来避免这种状态错位。

If the problem persists, or you are unsure which path applies, please report it with the application and version, Linux distribution, desktop environment, and whether other applications are affected. Include relevant libinput debug-events output if available.

如果问题仍然存在，或者你不确定该采用哪种处理方式，请提交问题，说明应用及版本、Linux 发行版、桌面环境，以及其他应用是否也有同样问题。如能提供相关的 libinput debug-events 输出，也请一并附上。

What should I do if another input device interferes with Smooth Scroll?

其他输入设备干扰 Smooth Scroll 时怎么办？

Some USB receivers, controllers, tablets, and other devices present mouse- or keyboard-compatible interfaces. If connecting one makes Smooth Scroll pause, wait for mouse movement, select the wrong mouse, or react repeatedly to an unstable device, add that model to Ignored Device Models in the Web Configurator.

某些 USB 接收器、游戏控制器、数位板或其他设备会提供兼容鼠标或键盘的接口。如果接入这类设备后 Smooth Scroll 暂停工作、等待鼠标移动、选错鼠标，或因设备不稳定而反复受到干扰，请在网页配置工具的忽略的设备型号中添加该设备。

Smooth Scroll will then leave every device with the same vendor and product ID alone. Keep the list empty unless a device actually causes a problem.

添加后，Smooth Scroll 将忽略具有相同厂商和产品 ID 的所有设备。如果没有遇到这类问题，保持列表为空即可。
